モジュール構成

各モジュールは単一責任原則に基づいて分割されています。

ファイル役割主な依存
main.js エントリーポイント・初期化 全モジュール
config.js 設定定数（差分色・サイズ制限等） なし
state.js アプリケーション状態管理・Logger なし
errors.js カスタムエラークラス定義 なし
error-handler.js エラーの一元処理・ユーザー通知 errors.js, state.js, ui.js
event-manager.js イベントリスナー管理・ドラッグ&ドロップ config.js, state.js, file-handler.js, navigation.js
file-handler.js ファイル読み込み・処理オーケストレーター ほぼ全モジュール
html-processor.js HTML サニタイズ・スタイルインポート config.js, state.js, errors.js, table-processor.js
table-processor.js 差分テーブル処理・固定ヘッダー・行の色取得 config.js, state.js, utils.js
diff-detector.js 差分ブロック検出・ミニマップマーカー生成 config.js, state.js, utils.js, table-processor.js
navigation.js 差分ナビゲーション・インターフェースリセット config.js, state.js, utils.js, ui.js, html-processor.js, diff-detector.js
progress-indicator.js プログレス表示（依存なし・独立モジュール） なし
ui.js UI 表示制御（メッセージ・ローディング等） config.js, state.js, utils.js
utils.js 汎用ユーティリティ・CSS 管理 config.js, state.js
_legacy/ について
_legacy/marker-manager.js は行単位マーカー機能（削除済み）の残骸です。 どのモジュールからも import されておらず、AppState.diffRows 等の削除済みプロパティを参照するため、 import・実行すると即座にエラーになります。参照禁止。

データフロー（ファイル処理）

ファイルが選択されてから差分表示までの処理ステップです。file-handler.js がオーケストレーターとして各モジュールを順に呼び出します。

ステップ処理内容担当モジュール進捗
readFileReader でファイルを読み込み・文字コード判定（UTF-8 / Shift-JIS）file-handler.js0〜20%
sanitizeHTML をサニタイズ（危険タグ・属性を除去）html-processor.js20〜40%
parseDOMParser で差分テーブルを抽出・スタイルをインポートhtml-processor.js40〜50%
detect差分ブロックを検出し AppState.diffBlocks に格納diff-detector.js50〜70%
markerミニマップマーカーを左右ペインに生成・配置diff-detector.js70〜90%
renderテーブルを DOM に挿入・ナビゲーションボタンを設定file-handler.js90〜100%

差分色定義（config.js）

差分色は config.js の DIFF_COLOR_MAP で一元管理しています。変更する場合はここだけ編集してください。

WinMerge のデフォルトカラースキーム（Default.ini）と一致しています。 WinMerge 内部は BGR 形式ですが、HTML レポート出力時に RGB に変換されるため RGB で定義しています。
typelabelcolor（RGB）HEX
changed変更行rgb(239, 203, 5)#efcb05
word変更行内差分rgb(241, 226, 173)#f1e2ad
del削除・追加行rgb(255, 160, 160)#ffa0a0
moved_from移動元rgb(255, 170, 130)#ffaa82
moved_to移動先rgb(200, 129, 108)#c8816c
separator区切り行rgb(192, 192, 192)#c0c0c0
⚠ isNeutral() の閾値について
table-processor.js の isNeutral() は閾値 240 で白・薄グレーを中立色と判定します。 差分色を変更する場合は、すべての色のチャンネル最小値が 240 を超えないことを確認してください。

テスト構成

種別ディレクトリツール環境
ユニットテスト tests/unit/ Vitest Node（DOM なし）
DOM テスト tests/dom/ Vitest + jsdom jsdom（DOM あり）

# カバレッジレポート付き
npm run test:coverage

# ファイル変更を監視
npm run test:watch

# E2E テスト
npm run test:e2e

デバッグ方法

URL に ?debug=true を付けるか、localhost / 127.0.0.1 で開くとデバッグモードが有効になります。

ブラウザコンソールで使用可能なデバッグ関数

wmv.debug.showBlocks()      // 差分ブロック統計・一覧
wmv.debug.visualizeBlocks() // ブロックを色枠で視覚化
wmv.debug.memoryStatus()    // メモリ使用量
wmv.debug.appState()        // AppState の状態ダンプ
wmv.debug.all()             // 上記すべて
